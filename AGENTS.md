# Контракт агента — seo-skills-ru

Читай этот файл целиком, прежде чем трогать сайт. Пакет публичный:
гигиена аудита, не приватная операционка.

## 1. Сначала контракт и плейбук

1. Прочитай корневой `SKILL.md`.
2. Выбери плейбук из `playbooks/`:
   - полный аудит → `full-audit.md`
   - только техника → `tech-only.md`
   - ошибки панелей → `panels-triage.md`
   - локалка / карты / каталоги → `local-geo.md`
   - сайт ещё не в проде → `prelaunch.md`
3. Подтяни только те `skills/*/SKILL.md`, которые плейбук вызывает.
   Не читай «всё подряд», если задача узкая.

## 2. P0-ворота обязательны

Перед семантикой, контентом, ссылками и «стратегией» прогони
`checklists/p0-gate.md`.

**Критичный fail = стоп.** Дальше только список блокеров и что
нужно от пользователя (скрин панели, доступ к коду, список зеркал).
Не маскируй fail красивым отчётом «в целом нормально».

## 3. Одна гипотеза, ноль выдуманных метрик

- Одна гипотеза за раз. Шаблон: `templates/hypothesis-card.md`.
- Не изобретай цифры Вебмастера, GSC, Метрики, ИКС, CWV, позиций.
- Нет скрина / экспорта / API-выгрузки → пиши `нет evidence`, не «скорее всего 92».
- Не называй точные % вклада факторов ранжирования. Этого нет в официальных доках.

## 4. Формат вывода

Итоговый документ — только `templates/report-audit.md`.
Ошибки кабинетов дополнительно своди в `templates/panel-errors-table.md`.

В отчёте обязательны:

- вердикт P0 (PASS / FAIL)
- evidence (URL, скрин, цитата HTML, дата снятия)
- next actions с владельцем (разработчик / контент / маркетинг / владелец кабинета)
- явный список того, чего не хватило на вход

## 5. Dead-list

Не предлагай и не «осторожно рекомендуй» пункты из
`references/dead-list.md`.

Коротко: Турбо, накрутка ПФ, PBN/биржи, thin programmatic,
FAQ rich result Google как цель, llms.txt как серебряная пуля,
автологин в панели, фабрика контента без редактуры.

## 6. Приватный контур

Если пользователь просит **пороги SOP, клиентские ТЗ, деньги-ниши,
коннекторы кабинетов, внутренние SLA** — ответь:

> Этого нет в публичном пакете. Живёт в отдельном приватном
> репозитории `seo1-private` и сюда не входит.

Не додумывай пороги «как в агентстве». Публичный слой = гигиена
и официальные определения продуктов (например, пороги CWV «good»
на web.dev — это не SOP агентства).

## 7. Входы, которых у агента нет по умолчанию

Агент **не логинится** в Яндекс.Вебмастер, Метрику, GSC, GA4,
Яндекс.Бизнес, Google Business Profile.

Проси у пользователя:

- скриншоты диагностик и покрытия
- экспорт sitemap / список исключённых URL
- доступ к репозиторию сайта или HTML money-шаблона
- регион продвижения и список зеркал
- факт: есть ли реклама на сайте (для `ru-ads-law`)

- Сомневаешься — маркируй `[офиц.]` / `[не офиц., гипотеза]`.
