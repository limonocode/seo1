# Как дополнять seo-skills-ru

Публичный слой. Пиши так, чтобы агент без доступа к кабинетам
и без секретов агентства мог повторить шаги.

## Правила

1. **Русский** — основной язык текстов. Короткие English-лейблы в именах файлов — ок.
2. **Без секретов.** Никаких `.env`, токенов, клиентских URL, логинов, порогов SOP.
3. **Без точных % факторов ранжирования**, если этого нет в официальной документации.
4. Маркируй утверждения: `[офиц.]` или `[не офиц.]`.
5. Не добавляй коннекторы кабинетов, скрейперы Wordstat, автологин.
6. Не предлагай пункты из `references/dead-list.md`.
7. Имя `Без названия-3` **нельзя заново добавлять** в коммиты
   (это сбрасывает дату на GitHub). Историческая заглушка — `archive/2017-stub/meta`.

## Куда класть изменения

| Что | Куда |
|-----|------|
| Новый узкий навык | `skills/<name>/SKILL.md` (80–200 строк) + строка в корневом `SKILL.md` |
| Новый прогон | `playbooks/*.md` — только последовательность вызовов skills/checklists |
| Галочки панели | `checklists/*.md` |
| Шаблон вывода | `templates/*.md` |
| Источник 2026 | `references/sources-2026.md` |
| Запрет | `references/dead-list.md` |
| Приватные пороги / ТЗ / SOP | **не сюда** — репозиторий `seo1-private` |

## Формат skill

У каждого `skills/*/SKILL.md` должны быть:

- frontmatter `name` + `description`
- зачем / когда / когда не
- шаги
- входы
- выходы
- стоп-условия
- ссылка на парный чеклист

Не раздувай skill в энциклопедию. Длинные цитаты — в `references/`.

## PR

- Одна тема на PR.
- Не коммить `archive/2017-stub/` «наведённый порядок», если не чинишь архив.
- В описании PR укажи, какой плейбук затронут.
- Лицензия текстов — CC BY-NC-SA 4.0, атрибуция limonocode / seo-skills-ru.

## Чего не принимать

- White-label переупаковка пакета под бренд агентства без согласования.
- «Точные» таблицы веса факторов.
- Скрипты обхода антибота / парсинга выдачи.
- Клиентские кейсы с живыми доменами и цифрами кабинетов.
