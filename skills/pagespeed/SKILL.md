# Skill: PageSpeed / CWV

## Зачем

Понять, не лежит ли money-шаблон в зоне **poor** по полевым данным.
Скорость — гигиена и UX; точный вклад в ранжирование Google/Яндекс
официально в процентах не публикуется.

## Когда

- Полный аудит, tech-only, жалобы на «долгую загрузку».
- Есть PSI / GSC CWV / CrUX.

## Когда не

- Новый домен без field-выборки — не ставь вердикт «CWV отличные»
  по одному Lighthouse.

## Шаги

1. Зафиксируй источник: field vs lab. Field главнее.
2. Сними mobile и desktop **отдельно**, money-URL и главную.
3. Сверь с порогами web.dev (p75):
   - LCP good ≤ 2.5s, poor > 4s
   - INP good ≤ 200ms, poor > 500ms
   - CLS good ≤ 0.1, poor > 0.25
4. LCP: что за элемент? Герой-картинка 3 МБ? Шрифт? Ответ сервера?
5. INP: сторонние виджеты, тяжёлые обработчики, чат.
6. CLS: баннеры, шрифты без reserve, вставки рекламы без места.
7. Lab (Lighthouse) — список подсказок, не оценка «97 = топ».
8. Одна гипотеза, если скорость — рычаг: например «отложить чат
   до взаимодействия», не «переехать на другой хостинг без evidence TTFB».

## Входы

- URL, скрин PSI / GSC
- Чеклист `checklists/pagespeed.md`
- HTML/код шаблона — желательно

## Выходы

- Таблица метрик с источником
- 0–1 тех. гипотеза или «field нет, только lab»

## Типичные находки

- Field нет (мало трафика), lab зелёный — вердикт «неизвестно».
- LCP = карусель 4K или веб-шрифт с длинным swap.
- INP валит виджет чата и три пикселя маркетинга.
- CLS от верхней рекламной шапки без reserved height.

## Как писать evidence

```
URL / устройство / источник (CrUX|GSC|PSI field|lab)
LCP / INP / CLS = … (единицы как в отчёте)
p75, не среднее
```

Скрин PSI прикладывает пользователь; не подменяй цифры «типичными».

## Ошибки агента

- Выдать lab за field.
- Смешать desktop и mobile в одну оценку.
- Пообещать рост топа после сжатия картинок.

## Стоп

- «LCP < 2.5 даёт ×3 к AI-цитатам» — не офиц., не писать как факт.
- Не обещай рост позиций от перевода жёлтого в зелёный.
