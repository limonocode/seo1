# Skill: локальные страницы

## Зачем

Сайт должен подтверждать гео, которое заявлено в карточках.
Не плодить тонкие «города».

## Когда

- Есть точка / выезд по городу / несколько филиалов.
- Плейбук `local-geo`.

## Когда не

- Федеральный ecom без самовывоза — не выдумывай локалку.
- Просьба «страница на каждый район МКАД».

## Шаги

1. Найди канонические контакты: одна главная страница / блок.
2. NAP текстом, единый формат телефона.
3. Филиалы: отдельный URL только если есть уникальные факты
   (адрес, часы, фото, как проехать). Иначе — список на одной странице.
4. Title/H1 «услуга в городе» допустимы, если страница не пустая
   и не копия соседнего города.
5. Не закрывай контакты в картинке или виджете без HTML-текста.
6. Сверь с карточками — `yandex-geo-neuro`.
7. Schema не должна показывать другой город «для SEO».

## Входы

- HTML контактов и городских URL
- Список филиалов от пользователя
- `checklists/geo-nap-catalogs.md`

## Выходы

- Карта URL филиалов: ок / дубль / doorway-кандидат
- Правки NAP

## Мини-выход (вставить в отчёт)

```
Контакты канон: [URL]
NAP текстом: да/нет
Филиальные URL: список + уникальность
Doorway-кандидаты: …
```

## Типичные находки

- 40 URL «ремонт в [город]» с одним абзацем.
- Филиал закрыт год назад, страница жива и в sitemap.
- Телефон 8 (800) на сайте, городской в Картах — без пояснения.
- Контакты только в footer-виджете на JS.

## Как писать evidence

Список URL + чем уникален каждый (адрес / часы / фото / прайс района).
Если уникального нет — пометка `doorway-кандидат`, не «контент слабый 3/10».

## Ошибки агента

- Рекомендовать «страницу на каждый район» без фактов.
- Игнорировать главную страницу контактов.
- Менять город в schema втайне от видимого текста.

## Стоп

- Ситидорвеи, подмена города в зависимости от IP без честного UI.
- Накрутка локальных отзывов.
