# Skill: поверхность безопасности

## Зачем

SEO-аудит часто первым видит открытый `.git`, staging в индексе,
смешанный контент, «сайт взломан» в Вебмастере. Это P0, не «потом».

## Когда

- Любой аудит, прелоунч, красная диагностика безопасности.
- Подозрение на хак (спам-дорвеи, странные редиректы).

## Когда не

- Просьба «проверь на дыры» в смысле пентеста — отказ, не нападай.
- Просьба обойти auth / WAF.

## Шаги

1. HTTPS: сертификат не протух (если видно в браузере/скрине),
   нет mixed content на money.
2. Зеркала не должны вести на чужой/старый хостинг.
3. Служебное: `/admin`, `/wp-login.php`, `/phpmyadmin`, staging-хосты —
   не должны отдаваться в индекс. Не подбирай пароли.
4. Попроси пользователя проверить, не отдаются ли `.env`, `.git/HEAD`,
   архивы `backup.zip`. Если он сам прислал 200 — P0: закрыть.
   Не скачивай секреты в репозиторий отчёта.
5. Панели: malware / hacked в Вебмастере или GSC — стоп контента.
6. Формы: базово есть ли капча/антиспам (по UI), без тестирования флудом.
7. В отчёте пиши «закрыть доступ», не «как эксплуатировать».

## Входы

- URL, скрины панелей безопасности
- `checklists/code-perf-security.md`

## Выходы

- P0-список поверхности
- Владелец: разработка / хостинг / кабинет

## Мини-выход (вставить в отчёт)

```
HTTPS / mixed: …
Служебные пути в индексе: …
Утечки (.env, .git, zip): спрашивали / подтверждено / нет
Malware в панелях: …
```

## Типичные находки

- Staging `dev.` в выдаче.
- Бэкап `site.zip` в корне.
- Смешанный контент: https-страница тянет http-скрипт.
- В Вебмастере «обнаружен вреносный код», на сайте — спам-доклейки.

## Как писать evidence

Путь и статус-код, которые **пользователь подтвердил**.
Если секрет попал в чат — скажи сменить и не повторяй значение.

## Ошибки агента

- Устроить пентест «заодно».
- Описать payload.
- Считать HTTPS достаточным, если админка в индексе.

## Стоп

- Эксплойты, PoC, брутфорс, сканеры уязвимостей «во всю катушку».
- Коммит секретов, которые нашли.
