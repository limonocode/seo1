# Skill: Google Analytics (GA4)

## Зачем

Если пользователь уже смотрит Google-трафик — проверить, что счётчик
на каноне и что есть конверсия. Не заменять Метрику.

## Когда

- Есть скрины GA4 или тег в HTML **и** цель включает Google.
- Сверяют расхождение Метрика vs GA4.

## Когда не

- Нет GA4 — не рекомендуй «обязательно внедрить» как P0 для Яндекса.
- Просьба слить сырые хиты / User-ID в отчёт.

## Шаги

1. Найди gtag / GTM в HTML канона. Запиши ID только если пользователь
   сам его прислал; не ходи в аккаунт.
2. Потоки данных: не должен считаться только staging.
3. Ключевые события: заявка / покупка. Без события гипотеза «трафик»
   слабая.
4. Источник organic google — только по скрину.
5. Расхождение с Метрикой на 10–30% без контекста — не «сломанный GA».
   Разные модели сессий. Пиши «разные системы, не сравнивать в лоб».
6. Не ставь GA4 north star, если бизнес крутится в Яндексе и заявки
   уже в Метрике.

## Входы

- HTML / GTM (опционально)
- Скрины отчётов, которые дал пользователь

## Выходы

- Есть/нет рабочего измерения Google-трафика
- Что не проверяли

## Мини-выход (вставить в отчёт)

```
GA4 на каноне: да/нет/не искали
Ключевое событие: …
Organic google по скрину: …
Сравнение с Метрикой: не делать в лоб
```

## Типичные находки

- GA4 стоит, Метрики нет — для Яндекса это дыра измерения ПС.
- Дубль GTM на thank-you, конверсии ×2.
- Organic google есть, Search Console не подтверждён — нельзя
  объяснить «какие запросы».
- Пользователь просит «точную атрибуцию SEO» из GA4 — вне гигиены.

## Как писать evidence

Период отчёта, имя потока, имя события. ID можно маскировать
(`G-XXXX`), если пользователь не просил светить полный.

## Ошибки агента

- Сделать GA4 обязательным P0 для сайта «только Яндекс».
- Объяснять расхождение с Метрикой как «кто-то врёт».
- Писать ключи API в отчёт.

## Стоп

- Хранить ключи Measurement Protocol.
- «Подмените реферер, чтобы был organic».
